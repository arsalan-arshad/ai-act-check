# DEV_CONTRACT — build contract for ai-act-check v0.1

Read `src/types.ts` first. It is the interface contract. Do not edit it (ask the orchestrator; optional-field additions only).

## Non-negotiable principles
1. Deterministic rules decide. A model never adds, removes or changes a finding.
2. Three outcomes only: `found`, `not_found`, `cannot_tell`. `cannot_tell` is never shown or worded as a pass.
3. Every finding carries evidence (URL, matched text/script/metadata, screenshot path, ISO timestamp).
4. Technical check, never legal advice. No code, string, report or comment may say a site is "compliant", "non-compliant", "violates", "illegal" or "passes the AI Act". Rules are "best-practice indicators" that *may* relate to Article 50; the legal basis is unverified (see docs/C1_FINDINGS.md: Art. 50(1) chatbot disclosure and 50(2) marking are *provider* duties, so a missing disclosure on a site is not necessarily the site owner's legal failing).
5. Public pages only. Respect robots.txt (no option to disable it). Rate-limit. No logins, no cookies/form values/personal data collected. Identify with an honest User-Agent.
6. Minimal dependencies: the only runtime dependency is `playwright`. Use Node built-ins (`util.parseArgs`, `fetch`, `node:http`, `node:fs`, `node:dns`, `node:net`). No other runtime deps.
7. Secrets: never print, log, serialize or put in reports `LLM_API_KEY` or any env value. Error messages must not echo secrets.
8. No real third-party sites in tests. Tests use only local fixture servers (127.0.0.1) and synthetic data. Never make network calls to real sites from tests or examples.
9. ESM, TypeScript strict, Node >= 20. Import with `.js` extensions (NodeNext).

## DEV-CRAWLER spec — `src/crawler/index.ts` exports `crawl(startUrl, opts)`
- Validate URL: only http/https. Reject others as `invalid_url`. Resolve host with `node:dns`; refuse loopback/private/link-local/unique-local/metadata (127/8, 10/8, 172.16/12, 192.168/16, 169.254/16, ::1, fc00::/7, fe80::/10, 0.0.0.0) unless `allowPrivate`. Check again against the final URL after redirects, and before each subsequent page.
- robots.txt: fetch `<origin>/robots.txt` with `fetch` (timeout 10s). Write your own minimal parser: groups by User-agent (match our product token `ai-act-check` first, else `*`), Allow/Disallow with longest-match precedence and `*` / `$` wildcards, Crawl-delay. 404/410 = no restrictions; 5xx/timeouts = be conservative: treat as disallow-all for this run (`startBlocked: 'robots_disallow'`, `robots.fetched=false`, document it). If the start URL is disallowed: no pages loaded, `startBlocked='robots_disallow'`.
- Playwright Chromium headless, one context, honest UA default `ai-act-check/<version> (open-source technical scanner; not legal advice)`. No cookies persisted, `acceptDownloads: false`, no permissions, `serviceWorkers: 'block'`. Never fill or submit forms; never click.
- Per page: `goto` with `waitUntil: 'load'`, then try `networkidle` (ignore its timeout), then wait `settleMs`. Then capture everything in `PageSnapshot` via `page.evaluate`: html, text, title, lang, scripts, links (absolute), images (src/alt/size/nearbyText), iframes (including inner text when the frame is accessible through `page.frames()` — Playwright can read cross-origin frames), domCandidates (generic heuristic `/chat|messenger|assistant|chatbot|bot\b|widget|helpdesk|livechat|copilot|support-?widget/i` on id, class, aria-label, title, and `data-*` attribute names/values; traverse **open** shadow roots; record `inShadowRoot`; dedupe; cap at 40 candidates), headers (lower-cased), and a viewport screenshot (1366x900) saved to `<outDir>/screenshots/page-<n>.png` (store the relative path).
- Link discovery: same-origin (same registrable host incl. `www.` equivalence) links only, strip fragments, skip obvious non-HTML (pdf, images, zip, mailto, tel), dedupe, prefer shorter paths and links whose text/href suggests AI/privacy/about/contact/help/support/chat/legal/terms. Up to `maxPages` (hard cap 25) pages. Honour robots for every URL (record `robots_disallow` in `skipped`). Main-document non-HTML content-type → `skipped: non_html`.
- Rate limit: wait at least `max(delayMs, crawlDelay*1000 capped 10000)` between page loads. Per-page failures are recorded in `loadErrors` / `skipped: load_failed`, never throw out of `crawl` for a page problem. Only throw for programmer errors. Always close the browser (finally).
- Images (`src/metadata/markers.ts` exports `extractImageMarkers(bytes: Uint8Array): ImageMarkers`): for up to `maxImagesPerPage` images fetch the first `imageMaxBytes` using `fetch` with a `Range` header (accept a 200 and truncate), only for same-origin or public hosts (apply the same private-address refusal), 8s timeout. Detect from bytes (pure function, unit-testable with synthesized buffers): JPEG APP11 JUMBF / "c2pa" / "jumb" box → `c2pa`; PNG `caBX` chunk or "c2pa" → `c2pa`; XMP packet (`<x:xmpmeta`) containing `DigitalSourceType` with IPTC term URIs (`trainedAlgorithmicMedia`, `compositeWithTrainedAlgorithmicMedia`, `algorithmicMedia`, `compositeSynthetic`) → `iptcDigitalSourceType`; text hints (case-insensitive) for `Midjourney`, `DALL-E`/`DALL·E`, `Stable Diffusion`, `Adobe Firefly`, `Imagen`, `Flux`, `Sora`, `ChatGPT`/`OpenAI` inside XMP/tEXt/iTXt/EXIF Software → `aiToolHints`; EXIF Software tag (JPEG APP1 Exif ASCII scan is fine, basic TIFF IFD parse). Never decode pixels. SVG/unknown → `markers: null`, `fetchStatus: 'skipped'`.
- Do not store raw image bytes in the snapshot.
- Export also `parseRobots` and `isPrivateAddress` for unit tests. Tests: use a local `node:http` server on 127.0.0.1 (random port) with `allowPrivate: true`, `delayMs` ~0..50, `settleMs` ~100. Cover robots parsing (precedence, wildcards, crawl-delay), private-address refusal, redirects, same-site filter, maxPages cap, non-HTML skip, shadow-DOM candidate capture, iframe text, marker extraction on synthesized buffers.

## DEV-RULES spec — `src/rules/index.ts`
Exports `RULES_VERSION = '0.1.0'`, `RULE_CATALOG: RuleMeta[]`, `runRules(crawl: CrawlResult): Finding[]` (pure, no I/O besides reading bundled JSON via `import ... with { type: 'json' }` or `readFileSync` relative to `import.meta.url` — it must work from both `src/` (vitest) and `dist/` (the postbuild copies `src/rules/data` to `dist/rules/data`); prefer `readFileSync(new URL('./data/x.json', import.meta.url))`).
One Finding per rule, site-level, in this order: CHAT-01, CHAT-02, MEDIA-01, MEDIA-02, PAGE-01.
- If `crawl.startBlocked` or `pages.length === 0`: every finding is `cannot_tell` with `reason` `'blocked_by_robots'` or `'no_pages_loaded'` as appropriate, empty evidence, `pagesEvaluated: []`.
- **CHAT-01** "Chat widget detected": match known vendors from `data/vendors.json` (≥30 vendors: Intercom, Drift, Tidio, Crisp, Zendesk, HubSpot Conversations, LiveChat, Tawk.to, Freshchat, Olark, Gorgias, Botpress, Voiceflow, Landbot, Chatbase, Ada, Kommunicate, Smartsupp, Userlike, Zoho SalesIQ, LivePerson, Salesforce Embedded Service, Dialogflow Messenger, IBM watsonx Assistant, Microsoft Copilot Studio/Web Chat, Respond.io, JivoChat, ChatBot.com/LiveChat bots, Botsonic, Quriobot, Certainly, Tars, Pandorabots, Sendbird, Smooch/Sunshine, Front Chat, Help Scout Beacon, Chatwoot, Rasa-based embeds, etc.) via script `src` host/path patterns, iframe `src` patterns, inline snippet markers, DOM id/class patterns. Each vendor entry: `id`, `name`, `scriptPatterns[]`, `iframePatterns[]`, `inlinePatterns[]`, `domPatterns[]` (all regex source strings, case-insensitive). The vendor patterns are best-effort and UNVERIFIED against live widgets; the file header (`_comment` field) must say so. `found` = ≥1 vendor match OR ≥1 generic `domCandidate`/iframe that is visible AND whose id/class/aria matches a strong chat pattern; evidence lists vendor name + script URL/iframe src/element description per page. The summary must say "chat widget detected", NOT "AI chatbot detected" — a chat widget may be human-staffed. `not_found` = pages loaded and nothing matched (summary says "no known chat widget detected in the rendered pages", limitation: late-loading, closed shadow DOM, consent-gated scripts). Never `cannot_tell` for plain absence.
- **CHAT-02** "AI disclosure text near a chat widget": if CHAT-01 is not `found` → `cannot_tell`, `reason: 'no_widget_detected'`, summary "Nothing to check: no chat widget was detected." If widget(s) found: search wording in `data/disclosure-phrases.json` (en, de, fr, es, it, nl, pt, pl; phrases like "AI assistant", "virtual assistant", "you are chatting with a bot/an AI", "powered by AI", "this is an automated assistant", "KI-Assistent", "Sie chatten mit einer KI", "assistant virtuel", "vous discutez avec une IA", "asistente virtual", "estás hablando con una IA", "assistente virtuale", "chatbot", "AI-assistent", "assistente virtual", "asystent AI"...) in: the text of widget-related domCandidates, text of the widget's iframes (when accessible), aria-labels/titles/alt of widget elements. Word-boundary, case-insensitive, accent-insensitive normalisation. `found` + evidence (matched text, location, URL), `needsHumanJudgement: true` (the rule cannot judge whether wording is adequate, timely, or clear). `not_found` ONLY when at least one widget UI text source was inspectable (non-empty text from a widget candidate or an accessible iframe) and no phrase matched. If the widget is detected but its UI text is not inspectable (cross-origin/closed launcher/empty) → `cannot_tell`, `reason: 'widget_ui_not_inspectable'`. Even `not_found` sets `needsHumanJudgement: true` (the chat UI may reveal text only after opening).
- **MEDIA-01** "AI-generation metadata on images": from `images[].markers`. `found` if any image has `c2pa`, an IPTC AI `iptcDigitalSourceType`, or `aiToolHints`. Evidence per image (metadata `field=value`). `not_found` if ≥1 image was read OK and none had markers (summary and limitation: absence of metadata does not show an image is human-made). `cannot_tell` (`reason: 'no_images_readable'`) if no image could be read. Note C2PA presence only means a manifest exists, not that the image is AI-generated; wording must say "content-credentials manifest present". Use `needsHumanJudgement: true` on `found`.
- **MEDIA-02** "Visible AI label near flagged images": if MEDIA-01 not `found` → `cannot_tell`, `reason: 'no_flagged_images'`. Else for each flagged image look at `alt`, `nearbyText` for label phrases in `data/ai-label-phrases.json` (multi-language: "AI-generated", "generated by AI", "created with AI", "made with AI", "KI-generiert", "généré par IA", "generado por IA", "generato dall'IA", "door AI gemaakt", "gerado por IA", "wygenerowano przez AI", "AI image", "Midjourney"...). `found` if all flagged images have a nearby label; `not_found` if ≥1 flagged image has none (evidence lists those images); mixed → `not_found` with the labelled ones also listed as evidence in the summary. `needsHumanJudgement: true`.
- **PAGE-01** "AI use / transparency page link": scan all `links` on all pages (text + href) with `data/page-phrases.json` ("ai policy", "ai transparency", "ai use", "responsible ai", "artificial intelligence", "ai act", "ai disclosure", "KI-Richtlinie", "Künstliche Intelligenz", "intelligence artificielle", "inteligencia artificial", "intelligenza artificiale", "kunstmatige intelligentie", ...). `found` + link evidence; `not_found` if no such link across the crawled pages (limitation: only crawled pages were checked); `needsHumanJudgement: true`; presence only, content quality not judged.
- Every Finding: `title`, `summary` (deterministic sentence), `pagesEvaluated` = URLs of pages evaluated, `evidence` capped at 20 items each (note the cap in the summary if hit). Evidence `capturedAt` = the page's `fetchedAt`. Add the page screenshot as a `screenshot` evidence item for the first page that contributed evidence (value = relative path).
- `RULE_CATALOG` has `limitations` and a hedged `legalNote` per rule, e.g. "Art. 50(1) AI Act (chatbot disclosure) is, per the unofficial text reviewed in docs/C1_FINDINGS.md, a provider duty; unverified against the Official Journal. Not legal advice."
- Tests: pure unit tests with hand-built `CrawlResult` objects (helper in `test/unit/rules/helpers.ts`): per rule one `found`, one `not_found`, one `cannot_tell` case, plus multi-language phrases, accent-insensitivity, evidence cap, blocked/no-pages paths, vendor pattern sanity (every vendor entry has ≥1 pattern and valid regexes), determinism (same input → deep-equal output).

## DEV-REPORT spec — `src/scan.ts`, `src/cli.ts`, `src/report/**`, `src/explain/**`, `src/util/**`
- `scan(url, opts)`: `crawl` → `runRules` → `buildReport` → write `report.json` and `report.html` into `outDir` (create dir; screenshots live under `outDir/screenshots`). If `opts.explain`, call the explainer; failures never fail the scan.
- `buildReport(crawl, findings, meta)` fills `Report` (schemaVersion 1; `summary` counts; `disclaimer` and `limitations` fixed text from `src/report/disclaimer.ts`). The disclaimer states: technical check, not legal advice, not a certification or compliance assessment; lists the pages checked; findings are best-practice indicators; "cannot tell" means the scan could not determine the answer and must not be read as a pass; regulation details unverified, verify with qualified counsel and official sources. Limitations list: only public rendered pages; max N pages; late-loading/closed shadow DOM/consent-gated widgets may be missed; chat UI text visible only after opening is not inspected; absence of image metadata proves nothing; a chat widget may be human-staffed; no judgement of wording adequacy; vendor list is best-effort.
- `renderJson(report)` stable key order, 2-space indent. `renderHtml(report)`: single self-contained file (inline CSS, no external requests, no JS needed), accessible, prints well, **all dynamic strings HTML-escaped** (page text may contain `<script>`), outcomes shown with text labels (not colour only), "cannot tell" shown in a neutral grey/amber style with the label "Cannot tell (not a pass)", disclaimer at top and bottom, per-finding evidence table, screenshot thumbnails via relative `<img src="screenshots/...">`, the pages-checked list, the rule catalog, the explanation block if present (labelled with its source).
- `src/explain/`: BYOK, provider from `LLM_PROVIDER` env (`anthropic` | `openai`), key from `LLM_API_KEY`, optional `LLM_MODEL`. Use plain `fetch` (Anthropic Messages API / OpenAI Chat Completions), base URL overridable by `LLM_BASE_URL` (used by tests with a local mock server). The model receives ONLY the findings array reduced to `{ruleId, title, outcome, summary, reason, needsHumanJudgement}` — no page text, no evidence. It must return JSON `{"items":[{"ruleId":"...","text":"..."}]}`. **Guard** (`guardExplanation(findings, items)`): same set of ruleIds exactly once each, no unknown ids, each text ≤ 600 chars, no banned phrases (case-insensitive: compliant, non-compliant, noncompliant, violat, illegal, unlawful, fine of, penalt, passes, passed, certified, safe harbou?r, "legal advice" only allowed inside "not legal advice"), and for `cannot_tell` findings the text must not contain pass-like words (pass, ok, fine, good, safe, compliant, no issue) and must contain a word from {cannot, could not, unable, unclear, not determine, undetermined}; for `found`/`not_found` the text must not contradict the outcome word (a `found` text must not say "not found"/"no ... detected" and a `not_found` text must not say "was found"/"detected" without negation — implement conservatively). On any guard failure, provider error, timeout (30s), missing key, or bad JSON: fall back to the deterministic `templateExplanation(findings)` and set `guardRejected` to a short reason (never include the key or response body secrets). The explanation can never alter `findings`; `scan` must deep-freeze or clone findings before the explainer to prove it.
- CLI `ai-act-check <url> [options]` using `util.parseArgs`: `--pages N` (default 10, 1..25), `--out DIR` (default `./ai-act-check-report-<host>-<yyyymmddThhmmss>`), `--json` (print the JSON report to stdout instead of the human summary; files still written; stdout must be pure JSON), `--explain`, `--delay-ms N`, `--timeout-ms N`, `--settle-ms N`, `--allow-private` (for local testing; prints a notice to stderr), `--no-html`, `--version`, `-h/--help`. Human summary to stdout: header with disclaimer one-liner, per-rule outcome lines using the words `FOUND`, `NOT FOUND`, `CANNOT TELL (not a pass)`, report paths. Exit codes: `0` scan completed, `1` internal error, `2` usage error, `3` scan refused or blocked (robots.txt disallow, private address, invalid URL, start page failed to load). Errors to stderr, never stack traces unless `DEBUG=1`; never print env values. `#!/usr/bin/env node` shebang. First line of any scan prints (stderr) the User-Agent in use and a reminder to scan only sites you are allowed to scan.
- Unit tests: arg parsing (including bad input), report building/summary counts, JSON stability, HTML escaping of hostile strings, disclaimer present, explainer guard with hostile model outputs (mock `fetch` via local http server and `LLM_BASE_URL`), key never appearing in any output.

## Style
Small modules, no dead code, comments only where the why is non-obvious. No TODO placeholders. Everything you write must be used and tested.
